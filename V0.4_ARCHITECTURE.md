# HDGL v0.4: True End-to-End Unified Transport Architecture

**Released:** May 8, 2026
**Previous:** v0.3 (Strand-Native HTTP Ingress)
**Status:** Production Ready ✓

---

## Executive Summary

HDGL v0.4 achieves true geometry-driven architecture by extending strand-based routing to the **transport layer**. All node-to-node communication (gossip, replication, fetch, health, metrics) flows through a **single unified HDGL protocol listener** instead of separate HTTP endpoints on different ports.

### Key Architectural Change

**v0.3 (Previous):**
- Application layer: strand routing (`phi_tau(path)`)
- Transport layer: conventional TCP on separate ports (`:8080` public, `:8090` gossip, `:8443` TLS, `:5353` DNS)
- Services identified by **port number** (port-based service ontology)

**v0.4 (Current):**
- Application layer: strand routing + lattice coordination
- Transport layer: **single unified HDGL socket** (configurable port, default `:8444`)
- All services identified by **frame type** (HDGL message ontology)
- **Frame routing:** `(strand_id, message_type) → handler` with geometry-driven dispatch
- No port-based service separation; ports are only bootstrap binding

## Architecture Components

### 1. HDGL Transport Frame Format

Binary protocol, length-prefixed, signed with CLUSTER_SECRET:

```
┌─────────────────────────────────────────────────────┐
│ [4B]  frame_size        (uint32)                    │
│ [1B]  version           (0x01)                      │
│ [1B]  frame_type        (0=INFO, 1=GOSSIP, 2=FETCH,│
│                          3=REPLICATE, 4=METRICS,    │
│                          5=HEALTH, 6=ERROR)         │
│ [1B]  strand_id         (0-7, geometry routing)     │
│ [1B]  reserved          (0x00)                      │
│ [4B]  authority_epoch   (lattice generation)        │
│ [4B]  source_ip         (uint32)                    │
│ [2B]  payload_length    (uint16)                    │
│ [2B]  timestamp_low     (uint16)                    │
│ [N B] payload           (JSON or binary)            │
│ [32B] hmac_signature    (SHA256)                    │
└─────────────────────────────────────────────────────┘

Minimum frame: 4 + 16 + 0 + 32 = 52 bytes
```

**Frame Types:**
- `HDGL_MSG_INFO (0)`: Node state query/response (health, latency, storage, known_nodes)
- `HDGL_MSG_GOSSIP (1)`: Peer announcement (coordinate lattice state across cluster)
- `HDGL_MSG_FETCH (2)`: Content read (strand-routed to authoritative node)
- `HDGL_MSG_REPLICATE (3)`: File migration / echo propagation
- `HDGL_MSG_METRICS (4)`: Performance stats (frame counts, pool reuse, latency)
- `HDGL_MSG_HEALTH (5)`: Liveness probe (ping for load balancers)
- `HDGL_MSG_ERROR (6)`: Error response (includes error_code, error_msg)
- `HDGL_MSG_RESERVED (7)`: Reserved for future expansion

### 2. Unified Transport Server (`hdgl_transport.py`)

Single TCP listener accepting HDGL frames with:

- **Port configuration:** `LN_TRANSPORT_PORT` (env var, default `:8444`)
- **Connection handling:** Async TCP accept loop with per-frame timeout
- **Frame multiplexing:** Dispatcher routes by `(strand_id, frame_type)`
- **Strand-aware routing:** Authority lookup via lattice for each strand
- **Connection pooling:** Per-strand outbound connections with reuse limits
- **HMAC validation:** All frames signed with `LN_CLUSTER_SECRET`, replay window ±30s
- **Metrics tracking:** Frame counts, routing decisions, pool statistics

**Handler Methods:**
- `_handle_info_frame()`: Respond with node state
- `_handle_gossip_frame()`: Update lattice, emit `_recv_gossip()`
- `_handle_fetch_frame()`: Route to authority, serve or proxy
- `_handle_replicate_frame()`: Store replica with Omega-TTL
- `_handle_metrics_frame()`: Return transport metrics
- `_handle_health_frame()`: Simple alive response

### 3. Transport Client (`hdgl_transport_client.py`)

Peer-to-peer frame sender with connection pooling:

- **Connection cache:** Per-peer socket pool with reuse limits
- **Retry logic:** 3 attempts with exponential backoff
- **Message sending:**
  - `send_gossip(peer_ip, gossip_data)` → `HDGL_MSG_GOSSIP`
  - `send_info_query(peer_ip)` → `HDGL_MSG_INFO`
  - `send_fetch(peer_ip, path)` → `HDGL_MSG_FETCH`
  - `send_replicate(peer_ip, path, data)` → `HDGL_MSG_REPLICATE`
  - `send_metrics(peer_ip)` → `HDGL_MSG_METRICS`
  - `send_health_probe(peer_ip)` → `HDGL_MSG_HEALTH`

### 4. Updated Host Daemon (`hdgl_host.py`)

Refactored to use unified transport:

- **Initialization:** `self.transport = HDGLTransportServer(...)` (replaces `node_server` + `native_server`)
- **Gossip:** `_gossip_self()` → sends `HDGL_MSG_GOSSIP` frames via `transport_client`
- **Peer queries:** `_fetch_node_info()` → sends `HDGL_MSG_INFO` frames
- **Receiving:** `_recv_gossip(data, peer_ip)` → handler called by transport server
- **Shutdown:** Unified `_shutdown()` stops single transport server

## Feature Highlights

### 1. Geometry-Driven Transport Multiplexing

Every HDGL frame carries:
- **Strand ID (0-7):** Routes to correct authority via lattice
- **Authority Epoch:** Ensures consistent authority during topology shifts
- **Message Type:** Determines handler dispatch

No port-based service separation; all routing is geometry.

### 2. Connection Pooling Per Strand

`StrandConnectionPool` maintains per-strand outbound sockets:
- Configurable pool size: `LN_TRANSPORT_POOL_SIZE` (default: 8)
- Reuse limit: `LN_POOL_REUSE_LIMIT` (default: 16)
- Metrics tracking: `reuse_count`, `mismatch_count`
- Automatic cleanup of dead connections

### 3. HMAC Frame Signing

All frames signed with `LN_CLUSTER_SECRET`:
- SHA256 HMAC over `timestamp:frame_body`
- Replay protection: ±30s replay window
- Silent rejection of corrupted/replayed frames

## Deployment

### Installation

```bash
sudo bash deploy_hdgl_v0.4.sh
```

Configurable via environment variables:
- `HDGL_LOCAL_NODE`: This server's IP (auto-detected if not set)
- `HDGL_PEER_NODES`: Comma-separated peer IPs
- `HDGL_TRANSPORT_PORT`: Unified listener port (default: 8444)
- `HDGL_FILESWAP_MAX_SIZE`: Swap size in GB (default: 10)
- `HDGL_CLUSTER_SECRET`: HMAC signing secret (auto-generated if not set)

### System Requirements

- Python 3.6+
- Bash
- 64-bit Linux (Ubuntu 18.04+)
- 2+ cores, 2GB+ RAM
- Network access to peer nodes on `LN_TRANSPORT_PORT`

### Firewall Configuration

Allow inbound on transport port:
- UFW: `ufw allow in 8444/tcp`
- iptables: `iptables -I INPUT -p tcp --dport 8444 -j ACCEPT`
- Cloud Security Group: Allow port 8444 from peer nodes

## Migration from v0.3

### Breaking Changes

1. **Port configuration changes:**
   - Old: `LN_HTTP_PORT` (:8080), `LN_NODE_PORT` (:8090)
   - New: `LN_TRANSPORT_PORT` (:8444)

2. **Service endpoints removed:**
   - Old: `http://<peer>:8090/gossip`
   - New: HDGL frame `HDGL_MSG_GOSSIP`
   - Old: `http://<peer>:8090/node_info`
   - New: HDGL frame `HDGL_MSG_INFO`

3. **Configuration file format:**
   - v0.3: Separate `site_config.json` + nginx config
   - v0.4: Unified `site_config.json` with `transport_port` field

### Upgrade Path

v0.3 → v0.4 requires:
1. Stop v0.3 service: `systemctl stop hdgl`
2. Run v0.4 deployment: `sudo bash deploy_hdgl_v0.4.sh`
3. Copy persistent state: `cp /opt/hdgl/lattice_state.db* /opt/hdgl/ (new install)`
4. Start v0.4: `systemctl start hdgl`

No data loss; fileswap content and lattice state preserved.

## Known Limitations & Future Work

### Current Limitations

1. **Timestamp truncation:** 16-bit timestamp in frame (limited precision for replay window)
   - Workaround: Use current time for replay check during deserialization
   - Fix planned: v0.5 with full 32-bit timestamp

2. **No transport-layer compression:** Frames not gzipped
   - Rationale: Payload usually small (<1KB); bandwidth not bottleneck
   - Revisit if cluster grows to 100+ nodes

3. **TCP-only (no QUIC yet):**
   - QUIC multiplexing planned for v0.5
   - UDP-based transport for lower latency

### Future Enhancements (v0.5+)

- [ ] QUIC transport substrate (UDP multiplexing)
- [ ] Symmetric multicast for gossip (reduce peer queries)
- [ ] Strand-aware congestion control
- [ ] Batch frame aggregation (reduce syscall overhead)
- [ ] Hardware acceleration for HMAC (if using specialized crypto hardware)

## Support & Troubleshooting

### Verify Transport is Running

```bash
# Check service status
systemctl status hdgl

# View recent logs
journalctl -u hdgl -n 20

# Test port connectivity
nc -zv 10.0.0.1 8444

# Check frame metrics
curl http://localhost:5353/hdgl/metrics  # if metrics endpoint exposed
```

### Common Issues

**Service fails to start:**
- Check logs: `journalctl -u hdgl -f`
- Verify port not in use: `netstat -tupln | grep 8444`
- Ensure `LN_LOCAL_NODE` is routable (not loopback)

**Peers not communicating:**
- Verify `LN_CLUSTER_SECRET` is identical on all nodes
- Check firewall allows port 8444 from peers
- Ensure peers can resolve each other's hostnames

**High frame loss / errors:**
- Check network MTU (should be ≥1500 bytes)
- Monitor kernel backlog: `netstat -s | grep dropped`
- Increase TCP buffer sizes: `sysctl -w net.ipv4.tcp_rmem="4096 65536 16777216"`
